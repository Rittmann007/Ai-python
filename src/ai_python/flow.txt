ingest:
takes the input data
|
chunks the input
|
embeds every chunk
|
stores the embedding with the corresponding input data and interviewID(for filtering)

chat:
takes the query
|
embeds it
|
matches with the other embeddings in the db filtered by interviewID
|
takes out the matching data
|
puts it in context along with query
|
gives to the llm, returns the result


ℹ️ here 3 type of input context is given by default to the llm
and semantic search can mixup the retrieved chunks based on the user query
from those 3, so for a single input context,its good.
